01 — THE IDEA

Some questions
need a little
instinct.

Should I read first?
How risky is this?
Does this need a bigger model?

These are small judgments between big steps. Hunch is built to make them locally, with Apple's on-device Foundation Model, before an agent commits to its next move.

It asks typed questions. It gets constrained answers. Then ordinary, testable code chooses the route.

A FEW GOOD QUESTIONS

Before the
next step.

What does “System 1” mean here?+

A small, fast judgment before a larger reasoning task. Hunch uses a local model to answer focused, typed questions about a task, so policy code can decide what should happen next.

Does Hunch replace my coding agent?+

Hunch is designed to sit alongside your agent. It supplies local judgments and, eventually, policy routes and compact context. Claude Code, Codex, OpenCode, and Cursor integrations are planned.

What works today?+

The Swift CLI classifies risk as readOnly, reversibleWrite, destructive, or sensitive. The daemon is a placeholder. Policy enforcement, generation commands, and agent integrations are still on the roadmap.

Does the classifier send my task to the cloud?+

The current classifier uses Apple's on-device Foundation Model. If that model is unavailable, it reports an error. Cloud handoffs are part of the future routing design, rather than an automatic fallback in the current CLI.

How does this go beyond a classifier?+

The same local generative model can also summarize logs and diffs, pack context, and draft small pieces of text. These are planned capabilities, alongside typed classification and deterministic routing.
